# M6 Multi-Code Incremental Review

- Version: 0.7.0
- Status: Complete
- Date: 2026-09-15

## Outcome

M6 turns the single-code review flow into a maintainable multi-code workflow. A review freezes exact
published rule-pack versions, identifies deterministic conflicts without inventing legal priority,
calculates which rules depend on changed facts, re-executes only those rules, and compares the result
with an immutable baseline.

## Delivered

- National, local, enterprise, and project authority markers on rule packs
- Project-aware published-edition recommendations with explicit reasons and warnings
- Clause-number-based comparison for two editions of the same standard
- Exact multi-rule-pack snapshots containing version, content hash, source clause, and authority
- Fact-to-rule dependency graphs derived from rule inputs, applicability, and expressions
- Deterministic conflict candidates for incompatible equality or allowed-value requirements
- Human conflict resolutions with selected rule, note, actor, and audit trail
- Unresolved conflicting rules return `manual_review_required`; no automatic legal precedence is used
- Replacement file versions mark verified facts backed by older versions as `stale`
- Baseline impact analysis with changed facts and affected/unaffected rules
- Incremental check runs that execute affected rules and trace copied unaffected baseline results
- Stable rule-code comparison with added, removed, regressed, resolved, changed, and unchanged states,
  plus a downloadable JSON comparison report
- An M6 React entry point for multi-pack selection, recommendations, incremental runs, conflicts, and
  comparison summaries

## Continuity audit

M6 does not introduce another file store, fact model, rule engine, or findings screen. Replacement
documents remain M1 `FileVersion` records. Regulation changes remain M2 `StandardVersion` and
`Clause` records. Dependencies are computed from the M3 rule definitions already executed by the
restricted deterministic engine. Changed M4/M5 evidence invalidates the existing `ProjectFact`, and
M5 `CheckResult` and Workbench remain the only result and review path.

Historical runs remain reproducible because project, rule-pack, and conflict-resolution snapshots
are never rewritten.
Incremental runs reference a baseline, freeze a new project snapshot, reuse the exact baseline pack
snapshots, and annotate whether each result was executed or copied.

## Safety boundaries

- Edition recommendations are decision support, not a legal applicability determination.
- Source authority is metadata and never silently resolves a conflict.
- Only structurally provable equality/set conflicts are detected; other conflicts require review.
- A stale fact is excluded from future snapshots but remains available for audit and historical runs.
- Incremental execution changes performance, not the expected result set or compliance semantics.
- Professional review and statutory approval remain outside the system boundary.

## Verification

- M0-M5 backend and frontend regression suites remain active.
- M6 Golden tests cover multi-pack conflicts, explicit resolution, dependency impact, selective
  execution, copied-result traceability, and before/after classification.
- Ruff, strict mypy, backend coverage, ESLint, Vitest, TypeScript, and production builds are enforced.
- The OpenAPI artifact is generated from the running application contract.
