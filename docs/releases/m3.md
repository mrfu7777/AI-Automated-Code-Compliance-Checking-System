# M3 Deterministic Compliance Review

- Version: 0.4.0
- Status: Complete
- Date: 2026-09-13

## Outcome

M3 turns published M2 clauses into reviewed, executable rule packages and evaluates them against
verified project facts. Every run freezes its inputs, produces one of five explicit outcomes, and
keeps links to both the regulation source and project evidence.

## Delivered

- Versioned draft, reviewed, and published rule packages
- Restricted JSON expression language without arbitrary code execution
- Applicability expressions, missing-data behavior, and safe length/area unit conversion
- Architect review gate and immutable published rule packages
- Clone-to-new-version workflow instead of editing published rules
- Ten fire-safety rule authoring templates with explicit non-authoritative status
- Append-only, manually verified project facts with supersession chains and evidence
- Asynchronous `check.run` jobs using the existing M1/M2 dispatcher and lifecycle
- Frozen project, rule, clause, and evidence snapshots with canonical input hashes
- Five result states: compliant, non-compliant, insufficient information, manual review required,
  and not applicable
- Evidence-rich execution traces and downloadable JSON result export
- React workflow for rule authoring, fact entry, execution, and result inspection
- Golden tests covering pass, fail, missing, and boundary cases for all ten templates

## Continuity audit

M3 reuses the M0 `RulePack`, `Rule`, `ProjectFact`, `ReviewPackage`, `CheckRun`, and `CheckResult`
entities. It consumes only published M2 `StandardVersion`, `Clause`, and `Evidence` records; it
does not re-read regulation PDFs, repeat OCR, or create a second clause store. `check.run` is a new
type in the existing durable `Job` pipeline. M4 can replace manual facts with extracted candidates
while writing to the same `ProjectFact` and `Evidence` contracts.

## Safety boundaries

- The ten templates are workflow examples, not approved interpretations of Chinese fire codes.
- An architect must bind each rule to the correct published clause and verify scope, threshold,
  unit, exceptions, dependencies, and tests before publication.
- Missing required facts never produce a compliant result.
- Unit incompatibility produces manual review rather than a guessed comparison.
- Published rules and completed run snapshots are immutable.
- Results support preliminary internal review only and do not replace statutory approval.
