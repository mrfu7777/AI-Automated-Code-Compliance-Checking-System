# M7 Release Candidate

Version: `0.9.0`

M7 hardens the continuous M1–M6 workflow for a controlled architect pilot. It adds API-key access,
role enforcement, security headers, readiness checks, short configurable downloads, actionable
missing-information output, structured pilot feedback, tenant-scoped audit/operations views,
worker-idempotency proof, optional-model timeout/rate-limit/circuit-breaker behavior, preliminary
report disclaimers, and database backup/restore automation.

The React workspace uses the same projects, immutable files, verified facts, published rule packs,
review snapshots, findings, evidence, and incremental checks. It adds session-scoped pilot-key entry,
missing-input actions, and architect feedback instead of creating a separate pilot application.

## Verification targets

- Production refuses unsafe development authentication and placeholder key configuration.
- Viewer writes are blocked; every existing resource query remains organization scoped.
- A completed persisted job cannot execute twice.
- Optional-model failure cannot block deterministic review.
- Five thousand deterministic checks complete within the pilot performance budget in the unit test.
- CI restores a PostgreSQL archive into an isolated database.
- Full M0–M6 backend and frontend regression remains mandatory.

## Honest acceptance state

The release candidate is technically ready for a controlled pilot, but the architect acceptance and
full PostgreSQL-plus-MinIO recovery drill remain pending. Synthetic tests cannot establish real-world
code accuracy, independent usability, or customer value. See the pilot acceptance record and known
limitations before handling authorized project material.
