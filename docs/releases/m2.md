# M2 Regulation Digitization

- Version: 0.3.0
- Status: Complete
- Date: 2026-09-09

## Outcome

M2 converts an immutable regulation PDF from the M1 file pipeline into a searchable,
human-reviewable clause tree. Each clause keeps page and coordinate evidence so future rule
authoring and compliance findings can cite the exact source.

## Delivered

- Existing `FileVersion` selected as a regulation source; no duplicate upload path
- Organization-scoped standards and independently versioned editions
- PDFium text extraction and page rendering with local RapidOCR fallback
- Repeated header/footer removal and deterministic chapter, section, and article segmentation
- Positioned `DocumentPage`, `Clause`, and `Evidence` records
- Clause search, correction, hierarchy editing, split, and merge APIs
- Before-value `ClauseRevision` history with reviewer, timestamp, and reason
- Review gate and immutable publication boundary
- Draft-only reparse operation
- One generic job dispatcher, lifecycle, retry API, audit trail, and React polling path
- React regulation library and clause review workspace
- Golden-set parser tests and end-to-end M2 API/worker tests

## Continuity audit

M2 deliberately reuses M1 `ProjectFile`, `FileVersion`, `ObjectStorage`, `Job`, `AuditEvent`,
failed-job retry, and browser polling. The former file-only dispatcher was removed and replaced
at every call site by a job-type-aware dispatcher. M1 metadata processing now also uses the
shared persisted-job lifecycle, so no dormant legacy state machine remains.

## Safety boundaries

- OCR output is always a draft candidate.
- Publication requires human review of every active clause.
- Published versions cannot be edited or reparsed.
- A parse with no numbered clauses fails visibly instead of publishing empty data.
- M2 structures source text; it does not yet interpret clauses as executable compliance rules.
