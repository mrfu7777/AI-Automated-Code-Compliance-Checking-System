# M8 Demonstration-Ready V1.0

Version: `1.0.0`

M8 completes the planned engineering stages without replacing the M1–M7 architecture. It adds an
idempotent, development-only guided scenario that uses the production domain model and then runs
through the existing persisted job, deterministic engine, evidence workbench, missing-information
list, and report exports. It also adds a release manifest, production-image corrections, tagged
container publishing, and a full-stack demonstration smoke test in CI.

## Delivered

- Synthetic, clearly labelled PDF regulation and project drawing generated at runtime.
- Normal `Project`, `ProjectFile`, `FileVersion`, `StandardVersion`, `Clause`, `RulePack`, `Rule`,
  `ProjectFact`, `Evidence`, `CheckRun`, and `CheckResult` continuity.
- Four expected outcomes covering compliant, non-compliant, and insufficient-information states.
- React guided-demo entry point and instructions.
- `/api/v1/release` mapping application, source revision, image, schema, and processor versions.
- Production API image now contains Alembic configuration and migrations.
- Production web image uses a relative `/api/v1` endpoint by default.
- Tag-triggered API and web image publication to GitHub Container Registry.
- Fresh-stack CI demonstration followed by database backup and isolated restore.

## Release boundary

This is a demonstration-ready engineering release. It does not assert that a real architect pilot,
20–30 production rules, the full database-plus-MinIO recovery drill, or statutory accuracy has been
accepted. Those professional and deployment-owner approvals remain recorded as pending. The demo
standard is synthetic and must never be presented as an enforceable code.

## Continuity

No demo-only result table, mock workbench, alternate rule evaluator, or second frontend was created.
Future V1.x work must expand reviewed rules and Golden Sets through the existing versioned lifecycle.
